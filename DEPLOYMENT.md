# Запуск закрытого MVP владельцем

В этой задаче ничего не опубликовано. Production-бот не запускался, рабочая БД не изменялась. Все проверки SQLite выполнены на временных синтетических данных.

## Настройка

Нужны Python 3.11+, зависимости `requirements.txt`, Node.js и зависимости Mini App из её lock-файла. Создайте виртуальное окружение и установите зависимости:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Передавайте переменные через окружение службы или PowerShell. Файлы `.env.example` — образцы; сами по себе они не загружаются сервером.

| Переменная сервера | Назначение |
| --- | --- |
| BOT_TOKEN | Секрет тестового или рабочего бота; только сервер |
| ADMIN_ID | Положительный Telegram ID владельца, подтверждающего оплату |
| KITCHEN_IDS | Telegram ID сотрудников кухни через запятую |
| BOT_USERNAME | Имя этого бота без @; используется для регистрации |
| MINIAPP_URL | Публичный HTTPS URL Mini App |
| API_ALLOWED_ORIGINS | Разрешённые origin Mini App через запятую, без пути и завершающего слеша |
| INIT_DATA_MAX_AGE | Срок initData в секундах, по умолчанию 3600 |
| API_BIND / PORT | По умолчанию 127.0.0.1 и 8080; за обратным прокси |
| DATA_DIR / DB_NAME | Постоянный каталог и имя SQLite; абсолютный DB_NAME имеет приоритет |
| TZ_OFFSET | Смещение времени, для Ташкента 5 |
| CLICK_SERVICE_ID / CLICK_MERCHANT_ID | Реквизиты ссылки Click |
| SUPPORT_CONTACT | Необязательный контакт помощи |
| CHANNEL_ID / ORDER_CHANNEL_ID | Каналы для существующих функций публикации/отчётности |

Клиент: задайте `NEXT_PUBLIC_API_URL=https://api.your-domain.example` при сборке, без `/api` в конце. Это публичный адрес, секреты бота в клиент не передавайте.

API и бот запускаются вместе: `.\.venv\Scripts\python.exe main.py`. Используйте ровно один polling-процесс. При запуске устанавливаются команды и Web App menu button. `/app` отправляет inline-кнопку Mini App. Открытие старой reply-кнопкой или обычным браузером допускает просмотр меню, но без подписанного initData оформление недоступно. [Механизм проверки Telegram](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app).

Обеспечьте HTTPS для клиента и API. Например, Caddy на том же сервере:

```caddyfile
api.your-domain.example {
    reverse_proxy 127.0.0.1:8080
}
```

Домен должен указывать на сервер; порты HTTPS доступны прокси. Прокси должен сохранять Authorization. Не включайте логирование этого заголовка. Разрешите точный origin клиента в API_ALLOWED_ORIGINS; wildcard не нужен. Изображения доступны с того же API по `/media/`. Способ размещения собранного клиента выбирает владелец; эта задача хостинг не меняла.

## Локальные проверки

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
node --experimental-strip-types --test miniapp/tests/*.test.mjs
node miniapp/node_modules/typescript/bin/tsc --noEmit --incremental false -p miniapp/tsconfig.json
```

Из каталога `miniapp`:

```powershell
node node_modules/oxlint/bin/oxlint app/page.tsx app/layout.tsx lib/api.ts lib/cart-model.ts lib/schedule.ts tests
node node_modules/vinext/dist/cli.js build
```

Для просмотра без Telegram запустите из корня `.\.venv\Scripts\python.exe tests/preview_api.py`. Он создаёт временную синтетическую БД и API на 8089, без polling. В другом терминале из `miniapp` задайте `$env:NEXT_PUBLIC_API_URL='http://127.0.0.1:8089'` и запустите `node node_modules/vinext/dist/cli.js dev --port 3000`. Откройте localhost:3000. Защищённое оформление в обычном браузере намеренно недоступно.

## Приёмка в тестовом Telegram

Используйте отдельный тестовый бот, синтетическую БД и HTTPS стенд с настоящим initData. Не отключайте проверку подписи.

1. Откройте `/app`, добавьте стандартный комплекс и измените состав. Проверьте дату, время, количество и серверную сумму.
2. Перед первым заказом передайте собственный контакт боту; откройте меню снова. Проверьте сохранённую корзину и фактический баланс.
3. Измените цену на сервере между расчётом и отправкой: клиент должен запросить повторное подтверждение суммы.
4. Оформите заказ, повторите после имитации потерянного ответа и перезагрузки: должен вернуться прежний номер без повторного списания бонусов.
5. Нажмите «Я оплатил»: состояние только «на проверке». Подтвердите оплату владельцем; проверьте QR.
6. Учётной записью кухни проверьте отсутствие доступа к оплате, телефонам, балансам, экспорту и рассылке. Проведите заказ через приготовление и готовность.
7. Сканирование QR только открывает карточку. Кнопка выдачи доступна уполномоченному сотруднику для оплаченного готового заказа; повтор не начисляет бонусы снова.
8. Проверьте «Мои заказы» и повторную отправку уведомления при недоступности Telegram. Чужие заказы недоступны покупателю.

Настоящие платежи и доставку сообщений Telegram локальные тесты не проверяют.

## Миграция, резервная копия, откат

Сохраните версии и все незакоммиченные изменения основного репозитория и отдельного `miniapp`. Остановите старую службу до обновления. Выберите постоянный каталог данных вне OneDrive, ограничьте доступ к нему. Перед миграцией создайте новый снимок:

```powershell
.\.venv\Scripts\python.exe backup.py "C:\путь\click_lunch_v6.db" "C:\ClickLunch\backups\before-mvp.db"
```

Инструмент использует SQLite backup API, проверяет целостность и не перезаписывает назначение. Храните резервные копии отдельно от рабочего диска. Не копируйте только основной файл работающей SQLite-базы вручную.

`init_db` при запуске добавляет недостающие поля оплаты и аудита подтверждения, таблицу черновиков и поля защиты повторов. Миграция повторяемая. Существующие заказы получают `legacy_unknown`: старые статусы, включая `paid`, не доказывают оплату. Исторические заказы требуют ручной сверки владельцем. Новые заказы имеют `pending`; подтверждение сохраняет ID владельца и время.

Для отката остановите приём и процесс, сохраните актуальный снимок и сверяйте все заказы/оплаты, появившиеся после обновления. Старый код не обеспечивает новую модель оплаты и выдачи: запускать его поверх новых незавершённых заказов небезопасно. Откатывайте согласованный комплект кода обоих репозиториев и совместимого снимка только после сверки новых операций. Восстановление выполняйте в новый файл, проверьте его целостность и укажите его через DB_NAME; не затирайте единственную рабочую копию.

## Ограничения

Click не подтверждается автоматически. Уведомления отправляются после сохранения в фоновой задаче; долговечной очереди повторов нет. После сбоя используйте «Мои заказы»/повторную отправку и список владельца. Списки ограничены: 30 заказов покупателя, 50 для рабочих списков. После истечения initData Mini App требуется открыть снова. До регистрации локально сохраняется только состав/дата/время/выбор бонусов, без комментария; после регистрации черновик хранится на сервере. Полная проверка линтером ранее выявляла 19 ошибок в общих UI-файлах вне этой доработки; проверка изменённых файлов проходит.
